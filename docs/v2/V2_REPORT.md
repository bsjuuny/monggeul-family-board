## 4. 공지톡 분석기 통합 방식

- 원본은 TypeScript 하나: `src/notices/analyzer.ts`(공지톡에서 가져옴) → `dates.ts`(날짜) → `digest.ts`(보드 요약, 서버 `clean_digest` 와 같은 모양)
- 브라우저: 붙여넣기·가져오기 때 바로 분석. HTTP LAN에서는 `crypto.subtle` 이 없어 순수 JS SHA-256(`sha256.ts`)으로 내용 해시
- 서버: `npm run build` 가 `dist-server/analyze.mjs` 를 만들고, 자동 수집은 `node` 로 실행(`analyzer_bridge.py`). node가 없으면 "분석 대기" → 보호자 브라우저가 처리
- 확인 필요 판정은 서버 한 곳(`review_reasons`)

### 추가 기능: 기상청 키를 설정 화면에서 넣기
금고 키로 미리 확인하려 했으나 권한 검사에서 막혀(다른 프로젝트 키 사용), 대신 owner가 설정 화면에서 키를 붙여넣게 했다. 저장 전 시험 호출, 틀린 키는 저장 안 함, 응답·로그에 키 없음, 지우기 가능(테스트).

### 재리뷰 3차 반영 (Codex 2차 재리뷰 대상)
- 행사 행을 위치가 아니라 내용(날짜·제목)으로 짝지음. 순서가 바뀌어도 연결이 섞이지 않고, 지운 행을 되살리거나 그 연결을 새 행사에 넘기지 않음(테스트)
- 기상청 키는 태블릿 자신(127.0.0.1)에서 연 화면에서만 받음: 평문 HTTP로 Wi-Fi에 키가 오가지 않게
- 기상청에 연결하지 못해 확인하지 못한 키는 저장하지 않음(기존 키 유지), 환경변수 키 사용 중에는 화면 저장을 막고 안내
- 남은 한계: 공지 삭제 시 캘린더 정리는 여러 일정을 하나씩 처리하므로 중간 실패 시 일부만 정리될 수 있음(이 경우 공지는 지우지 않으므로 다시 시도하면 이어서 정리됨)
